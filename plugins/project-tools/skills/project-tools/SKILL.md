# Инструменты проекта

Что подключать, решает карта стеков `stacks.json` плагина project-tools, а не ты: команда пишет только её записи.
Своих серверов в `.mcp.json` руками не добавляй и в `.claude/settings*.json` одобрений не вписывай.

1. Посмотри, чего не хватает: `project-tools check` (из корня проекта или `--dir <папка>`). Код выхода 3 —
   есть что подключить, 0 — всё по карте, 2 — файл настроек битый (ничего не трогай, покажи ошибку владельцу).
2. Покажи владельцу строки «Нужно» и заметки «·» как есть, коротко: что появится и зачем.
3. Подключай, только если ты в сессии владельца без роли Пантеона и он согласен (просьба «настрой проект» —
   уже согласие): `project-tools apply`. Отличие от карты в готовой записи меняй только по его слову:
   `project-tools apply --update <имя>`.
4. После apply скажи: серверы заработают в новой сессии; общие файлы (`.mcp.json`, `.claude/settings.json`,
   `.codex/config.toml`) — для коммита, `settings.local.json` личный и в git не идёт. Сам не коммить без просьбы.

## В окне роли Пантеона (координатор, лид, разработчик)

`apply` там не сработает: песочница Claude Code и guard (правило protect-config) запрещают ролям запись в
`.mcp.json` и `.claude/settings*.json`. Обходить запрет другой командой нельзя. Запусти `project-tools check`
и поставь владельцу вопрос на доске: что подключить, зачем, готовая команда `project-tools apply --dir <папка>`.

## Нового инструмента нет в карте

Не подключай его мимо карты. Опиши находку (что, для какого стека, ссылка на пакет) — metis-pantheon добавит
запись в `stacks.json` после «да» владельца. Свежие версии закреплённых пакетов: `project-tools outdated`.
