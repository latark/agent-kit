# Харон: браузер владельца для ролей (`pantheon browser`)

Харон (роль `charon`, код — `plugins/pantheon/lib/browser.py`) работает в Comet или Chrome владельца со входами через
демон удалённой отладки. Окно роли пароля и порта демона не видит: оно кладёт заявку в ящик, а плановый проход вне окна
выполняет её и пишет итог. Чтение (health, open, read, eval) описано в шапке browser.py и в README репозитория. Здесь —
действия на страницах (metis-0765): нажатие, ввод, отправка формы и удаление, их правила и модель угроз.

## Решение владельца 05.11, дословно

«нужно сделать чтобы запрашивалось touch id, либо я мог ответить "да", оплату вообще запретить делать, это только я
вручную должен иметь возможность сделать. отправку формы - если форма обычная, то только через мой "да" или touch id.
если форма важная, то только я могу ее сделать, никакое touch id или "да" работать не должны. удаление 1 элемента
через отдельный touch id или "да", удаление пачки элементов только через "да". также нужно учесть минимизацию "да"
или touch id, то есть условно 1 разрешение на все поручение и потом для каждой отправки формы/удаления отдельные
touch id/"да"» (карточка metis-0765, журнал 05.11 13:23).

## Правила

| Действие | Что нужно | Touch ID | «Да» |
|---|---|---|---|
| Поручение `allow` | одно на задачу, сайт и список действий, срок 24 ч | да | да |
| Нажатие `click`, ввод `type` | поручение с этим действием | — | — |
| Отправка обычной формы `submit` | поручение и отдельное согласие на каждую отправку | да | да |
| Удаление одного элемента `delete` | поручение и отдельное согласие на каждое удаление | да | да |
| Удаление пачки | поручение и отдельное «да» на каждую пачку | нет | да |
| Важная форма | только владелец сам | нет | нет |
| Оплата | только владелец руками | нет | нет |

Команды (окно роли и сессия владельца; `--task ID` обязателен; действие — во вкладке, которую открыл `open`):

```
pantheon browser allow САЙТ ДЕЙСТВИЯ --task ID --why "цель"   поручение: ДЕЙСТВИЯ — click,type,submit,delete через запятую
pantheon browser click СЕЛЕКТОР --task ID                     флажок, переключатель, label к ним, ссылка того же сайта
pantheon browser type СЕЛЕКТОР ТЕКСТ --task ID                ввод в текстовое поле или textarea
pantheon browser submit СЕЛЕКТОР --task ID                    нажатие, которое отправляет форму (любая кнопка)
pantheon browser delete СЕЛЕКТОР --task ID                    нажатие, которое удаляет
```

У allow, submit и delete ожидание итога по умолчанию — 300 с: проход ждёт пальца в окне Touch ID до 120 с.

### Поручение

`allow` просит одно разрешение на всё поручение: задача, сайт (с поддоменами) и список действий. Проход сначала ищет
«да» владельца окном вопросов на вопрос, который начинается ровно с `[ID] Поручение Харону на <сайт>: <действия>.`
(ответ не старше 24 ч). Нет — показывает окно Touch ID «Харон (окно), задача ID: поручение на <сайт> — <действия>.
Цель: …». Владельца нет у Mac (простой больше 5 мин), помощника нет или окно не показать — отказ с точным текстом
вопроса, который Зевс задаёт окном вопросов. Поручение живёт 24 ч от согласия и хранится в
`STATE/browser/mandates/` (пишет только проход). Сайт поручения — сайт, который роли можно читать.

### Отправка и удаление

Каждая отправка и каждое удаление — своё согласие. Проход:

1. Проверяет поручение, адрес вкладки и вид формы (классификатор ниже). Оплата и важная форма — отказ сразу.
2. Ищет выданный раньше код вопроса на эту же отправку: задача, браузер, сайт, путь и запрос адреса, селектор, вид
   и отпечаток полей формы те же, код не использован и не старше 24 ч. На вопрос с этим кодом есть «да» владельца,
   полученное после выдачи кода, — отправляет. Код помечается использованным до нажатия: одно «да» — одна отправка.
3. Иначе, кроме удаления пачки, показывает окно Touch ID с адресом, видом действия, надписью кнопки и полями формы.
   Палец — проход снова снимает отпечаток формы и адрес; они те же — нажимает. Отказ в окне — отказ заявки.
4. Окно не показать, владельца нет у Mac, время вышло, а также всегда для пачки — проход выдаёт код и отвечает
   отказом с точным вопросом для Зевса: `[ID] Отправить форму на <сайт><путь>? Код <код>. Кнопка «…». Поля: …`
   (удаление — `[ID] Удалить на …`, пачка — `[ID] Удалить пачку (N) на …`). Владелец отвечает «да» окном вопросов,
   роль повторяет ту же команду. Повтор с той же формой получает тот же код, а не новый вопрос.

Отпечаток формы — sha256 от полей формы цели (без скрытых полей и паролей): имя, тип, значение, отметка, выбранные
пункты, текст редактируемых блоков, плюс адрес отправки формы и надпись кнопки. Цель без формы — поля всей страницы.

### Классификатор формы

Классификатор работает в проходе (Python), страница отдаёт только факты: адрес, теги и атрибуты цели и её предков,
поля и кнопки формы, заголовок. Порядок: оплата → важная → удаление (пачка или один) → обычная; срабатывает первое.

- **Оплата** (`PAY_*` в browser.py): поле карты (autocomplete `cc-*`, имя или подпись «card number», CVV, CVC,
  «номер карты», «срок действия», «держатель»); платёжный сайт (pay., payment., checkout., 3ds., acs., yoomoney,
  yookassa, qiwi, paypal, stripe, cloudpayments, robokassa, СБП nspk, онлайн-банки) у страницы или у адреса отправки
  формы; путь `/pay`, `/payment`, `/checkout`, `/billing`, `/oplata`; надпись цели или кнопки формы «Оплатить»,
  «Купить», «Заплатить», «Оформить заказ», «Пополнить», «Продвинуть», «Подключить тариф», Pay, Buy, Checkout,
  Place order, Top up.
- **Важная** (`IMPORTANT_*`): поле пароля, autocomplete `current-password`, `new-password`, `one-time-code`, поле
  «код из СМС», «код подтверждения»; сайт входа или госкабинет (gosuslugi.ru, nalog.gov.ru, nalog.ru, sfr.gov.ru,
  rosreestr.gov.ru, my.arbitr.ru, mos.ru, хосты id., login., auth., oauth., passport., accounts.); путь `/login`,
  `/signin`, `/auth`, `/register`, `/signup`, `/password`, `/security`, `/reset`, `/account/delete`; надпись цели,
  кнопок формы, заголовка формы или главного заголовка страницы: вход, регистрация, пароль, смена или изменение
  почты, телефона, номера; договор, оферта, подписать, электронная подпись; заявка на участие, подать заявку, торги,
  аукцион, ставка, задаток; перевод денег, перевести, вывод средств; удалить аккаунт или профиль, закрыть счёт;
  доверенность, расторгнуть, отказ от, жалоба, иск, заявление, декларация; кредит, займ, ипотека, залог;
  подтвердить сделку, операцию или перевод.
- **Удаление** (`DELETE_WORDS`): надпись, aria-label, title, value, id, name или class цели — «удалить», «удаление»,
  «стереть», «очистить», «уничтожить», delete, remove, erase, trash. Команда `delete` — удаление всегда.
  **Пачка** (`BATCH_WORDS`): в надписи «все», «выбранные», «отмеченные», all, selected, checked или число от 2; или
  в форме цели (без формы — на странице) отмечено два флажка и больше.
- **Обычная** — всё остальное, в том числе сообщения людям, отзывы и публикации: владелец видит текст полей в окне
  Touch ID или в вопросе.

Для click и type классификатор тоже работает: флажок или поле в форме оплаты или в важной форме — отказ.

### Нажатие и ввод

- `click` — вид цели только по тегу: `input` checkbox или radio, `label`, чей control — такой input, ссылка `a[href]`
  на тот же сайт (http(s), без onclick, target и download). ARIA-роль вид не расширяет: `button[role=tab]`,
  `div[role=switch]`, `a[role=button]` — отказ «это submit». Цель — элемент под центром селектора
  (elementFromPoint) и ближайший интерактивный предок; выше цели не должно быть кнопки, ссылки, summary, select,
  элемента с ролью виджета или onclick: нажатие всплывёт до него.
- `type` — только `input` текстового вида (text, search, email, tel, url, number) без роли и `textarea`; пароль,
  поле карты и одноразовый код — отказ классификатором. Перевод строки в `input` — отказ (Enter отправил бы форму).
  Ввод — `Input.insertText` после фокуса; фокус не встал на поле — отказ.
- Прокрутка к цели — `scrollIntoView({behavior: 'instant'})`: плавная прокрутка сайта (CSS scroll-behavior) не
  сдвигает точку. Перед нажатием проход второй раз снимает рамку цели и elementFromPoint; рамка сдвинулась или точку
  закрыл другой элемент — отказ без нажатия.
- После нажатия адрес вкладки сверяется со списком чтения: увело на чужой сайт — about:blank и отказ.
- Проход зовёт `/cmd` демона только с `Input.dispatchMouseEvent` и `Input.insertText` (`CMD_ALLOWED`);
  `/close`, `/events`, `/console` — нет.

### Touch ID

Окно — тот же помощник, что у слияния ядра: `merge_mod().helper()` собирает и проверяет `STATE/bin/pantheon-touchid`
из `lib/touchid.swift`. Харон передаёт помощнику третий аргумент — надпись кнопки отказа «Отказать» (у слияния
по-прежнему «Не сливать»). Владелец у Mac — простой меньше `PRESENT_SEC` слияния (5 мин). Текст окна: сначала то, что
пишет проход (окно, задача, сайт, путь, действие), затем надпись кнопки и поля формы в кавычках, всего до 400 знаков.
Окно держит проход до 120 с: другие заявки в это время ждут.

## Модель угроз действий

Граница — как у guard: защита от ошибки агента и от указаний со страницы, которые агент принял за свои, а не от
намеренного обхода. Тест — `plugins/pantheon/tests/test_browser.py`, проверка с меткой строки («[K1] …»).

### K. Вид нажатия

| # | Обход | Защита | Тест |
|---|---|---|---|
| K1 | селектор на span внутри кнопки отправки | цель — elementFromPoint и ближайший интерактивный предок: кнопка над span решает | [K1] |
| K2 | кнопка с ARIA-ролью (`button[role=tab]`, `button[role=switch]`, `a[role=button]`) проходит как вкладка или флажок | вид только по тегу; роль у разрешённого тега — только родная (checkbox, radio, switch у input; link у a) | [K2] |

### Остаток

- Обработчики, повешенные скриптом (addEventListener) на предка, классификатор не видит: флажок с автосохранением
  настроек срабатывает по поручению с click.
- Поля select и редакторы с contenteditable не заполняются (type — отказ): такое поле — рука владельца.
- Демон и живой браузер в тестах — подделка; живой проверки в Comet нет (браузер владельца в тестах не трогается).
