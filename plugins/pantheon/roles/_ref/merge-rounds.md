# Круги ревью, возврат и находки Б/Д/С

Вынесено из общей части «слияние» (metis-0386): читай этот файл перед повторным или узким вызовом argus, после первого
возврата argus и когда сортируешь находки ревью. Что и сколько argus звать — в твоей роли, раздел о слиянии.

- Повтор — только при новом диффе. Подтянул main — сначала тесты на новом head и слияние: если собственный дифф PR
  тот же, шлюз переносит «принять» сам (README guard), argus не нужен. Отказ «нет «принять»» — тогда узкий повтор:
  новый head только из-за подтягивания main, и только если журнал
  шлюза на прошлом head чист: в `pantheon review status <owner/repo> <N>` строка «итог на <прошлый head>» — «вернуть
  0», а «принять» не меньше числа argus круга (в ядре — два, по строке «для PR ядра»). Иначе — полный круг: слова лида
  и отчёты журнал не заменяют. Поручение «Узкий повтор: прошлый head <sha>»: пути отчётов не называй — argus опирается
  на последний свой отчёт по этому PR. Его ведёт тот же argus, тем же вызовом через SendMessage (в ядре — оба), по
  дельте; дельту он сверяет вместе с merge-коммитами, тесты на новом head — запись шлюза, пункт 1 о шлюзе в разделе о слиянии твоей роли. Нового
  диффа нет (head тот же) — повтора нет, argus не зови.
- Вне ядра: два круга подряд вернули только за формулировки, без бага, обхода и теста, — третьего полного круга не
  зови. Оставшиеся замечания по тексту решает лид или координатор и пишет решение в план эпика, у задачи без эпика —
  в её журнал. Текст поправил — поручение «Узкий повтор: прошлый head <sha>, правка текста: <файл:строка>, решение:
  <файл плана>, вернули: <agent_id/сессия, …>». Решил оставить как есть — поручение «Узкий повтор: тот же head <sha>,
  решение: <файл плана>, вернули: <agent_id/сессия, …>» (единственный повтор на том же head: он снимает «вернуть» в
  журнале шлюза). В «вернули» — каждый argus, которого ты продолжил, по 8 знаков agent_id и сессии, как у вердикта в
  `pantheon review status`; argus сверит их с рецензентами «reject» на прошлом head.
- Оба пути ведут все вернувшие argus, каждый — тем же вызовом через SendMessage: шлюз узнаёт argus по вызову, и
  «вернуть» прежнего вызова новый вызов не снимет. Исключение — путь «правка текста» (код другой), когда вызов не
  продолжить: новый argus сам достаёт отчёты прежних через `pantheon review report` (абзац «Вызов не продолжить»);
  путь «тот же head» — только прежние вызовы. Не продолжил хоть одного вернувшего и отчёта его нет — полный круг: на новом head
  шлюз прошлые «вернуть» держит. «Принять» другого argus снимает их, только если код отличается от кода, на котором
  вернули. argus сам открывает свои отчёты двух прошлых кругов. Замечание с багом, обходом,
  тестом или мутантом — не формулировка: он ставит «вернуть» с причиной «не формулировка — полный круг».
- В ядре формулировку не решает лид: текст ядра и есть правило. Новый head в ядре, кроме подтягивания main,
  проверяют оба argus: после возврата по коду — повторным кругом (ниже), иначе обычным кругом. Повторный круг в ядре —
  полный, по всему диффу PR (metis-0669); вне ядра — только правка и то, что она задевает.
- Повторный круг после возврата (metis-0420): автор поправил код, за который вернули, — продолжи тем же вызовом через
  SendMessage (или новым argus с `pantheon review report`, когда вызов не продолжить — ниже) каждого argus прошлого
  круга, в ядре — обоих, и того, кто принял: шлюз считает
  последний вердикт каждого argus на новом head. Поручение «Повторный круг: прошлый head <sha>, правка:
  <файл:строка>, вернули: <agent_id/сессия, …>». В «вернули» — каждый argus, чей последний вердикт на прошлом head —
  «вернуть», по 8 знаков agent_id и сессии, как у вердикта в `pantheon review status`; argus сверит их с рецензентами
  «reject» на прошлом head; не совпало — он ставит «вернуть» с причиной «вернувший argus не продолжен — продолжи его»,
  а не принимает сам. argus берёт свой прошлый отчёт и дельту прошлый head → новый head, а не весь дифф; выданное не
  повторяет. Это вне ядра; в ядре он читает весь дифф PR заново. Дельта шире заявленной или задевает новые файлы — он сам ведёт полный
  круг. Тесты на новом head — запись шлюза, пункт 1 о шлюзе в разделе о слиянии твоей роли.
- Вызов не продолжить (metis-0602): SendMessage отвечает «No transcript found» — после /clear, перезапуска, пауза
  дольше сессии. Это не повод для полного круга: отчёт прежнего argus лежит в его транскрипте. Зови нового argus
  повторным кругом, как выше, с «вернули: <пары>» — файлов и отчётов в поручении не передавай: argus сам вызывает
  `pantheon review report <owner/repo> <N> <agent8>/<сессия8>` на каждую пару из «вернули» (в ядре — и на принявшего,
  которого заменяет), сверяет «Head:» каждого отчёта с прошлым head и закрывает Б всех вернувших: его одно «принять»
  на другом коде снимает все их «вернуть» (шлюз, другой argus и код отличается). В ядре — по одному новому argus на
  каждого заменяемого. Любой отказ команды по любой паре (нет файла, нет отчёта, «Head:» не совпал) — полный круг.
  «Узкий повтор: тот же head» без прежнего вызова не получится: код тот же, и новый argus «вернуть» не снимает.

Находки ревью: Б, Д, С (metis-0406, владелец 24.10 04:18; круги и правило по риску — metis-0393, накопление мелких
правок — metis-0401):
- argus классифицирует каждую находку: Б — блокер (обход защит, регрессия, потеря данных или вердикта, секреты и личное,
  дефект нового кода на основном пути, неверно по критерию готовности), Д — долг, С — к сведению. Из находок по коду «вернуть» он ставит только при Б; прочие возвраты argus (тест, узкий повтор, перечень, Opus) остаются.
- После каждого возврата лид сортирует: Б правит автор в этом PR. Д — задача `pantheon task new` с полем «из ревью PR
  #N» и областью (guard/шлюз, роли, плановый проход…); в PR их не тянуть. Есть Д без Б — это «принять»; сливай по правилам раздела о слиянии твоей роли (все позванные argus, тесты, PR ядра — владелец), задачи заведи.
- С круга 3, а также при новой находке в новом коде, лид обязан рассмотреть «сузить»: вырезать из PR часть, которая
  плодит новые края, и вынести её задачей (как metis-0384, metis-0393). Круг 4 и дальше без сужения — только словом
  владельца. Решение «сузили» или «не сузили, потому что…» — в план или журнал задачи.
- Д копятся в пачку по области: раз в неделю или при пяти задачах в области — один исполнитель, один круг ревью на
  суммарный дифф.

## Пачка — одна ветка и один PR (metis-0757)

Задачи пачки (story) не получают своих PR: они идут коммитами или слияниями в ветку `batch/<story-id>`
(`pantheon batch start <story-id>`), на каждую — узкие тесты. Круги ревью, полный набор тестов и `pantheon merge request`
— один раз, на PR пачки (`pantheon batch pr <story-id>`). Коммит или влитая ветка задачи называет её номер: `Closes`
команда ставит только задачам с номером в коммитах ветки, остальные — «не вошли» и этим PR не закрываются. Всё сказанное выше о кругах
argus относится к этому PR целиком. Задача вне пачки — свой PR, как прежде.

## Тело PR: Closes и «часть» (metis-0583)

Тело PR называет каждую задачу, которую он закрывает: `Closes <id>` или списком `Closes metis-0522, metis-0534 и 0535`.
Это правило — для PR в любом репозитории направления (agent-kit, BA, сайт): автозакрытие читает тела PR всех репозиториев из [merge_repos].
По этой строке плановый проход ставит задаче done при слиянии, и под общей веткой тоже (metis-0583). Слово «часть» в
теле — все задачи PR остаются открытыми; если частичная только одна — отдельный PR или без Closes и без её номера в имени ветки.
