# guard

Правила, которые Claude Code проверяет сам, а не на память модели. Хук PreToolUse (Bash, Write, Edit, MultiEdit,
NotebookEdit, Read, Grep, Glob, WebFetch, Agent, Task, Skill) и Stop; весь код — `hooks/guard.py`, его шапка
перечисляет правила.

## От чего защищает (модель угроз, SEC-27, решено 14.10)

guard ловит **ошибки агента**: запись не в своё направление (domain), правку чужого файла штаба, файла задачи
мимо `pantheon task` и доски или журнала ваших слов любой сессией Claude (pantheon-acl), правку защит не той ролью (protect-config), команду пульта не той ролью, чтение ключей
(tg-secret; ролям из демона tg-readd — только `status` и `kickstart`), пометки об авторстве Claude, свой dev-сервер; с шага 1.2 — по ролям Пантеона: личное (private: `me/`,
ключи git-crypt, журнал штаба — только hq, chiron в окне штаба и mnemo-brain; ключи — никому из ролей), Telegram
и коуча chiron вне своего окна (hq-telegram, chiron — раздел «Окно штаба»), браузер владельца
(cdp-role: демон — только мастерская; прямой отладочный порт и WebFetch на локальные адреса —
никому; ловит по номеру порта, а не по записи адреса; у WebFetch — ещё имена вроде localtest.me и nip.io, а при Surge
имена разрешаются в 198.18/15 и настоящий адрес не виден — это предел правила), push (только в свою ветку, не в main/master, без force — в том
числе `+ветка` — и удаления; `gh api` с записью — нет; `gh pr merge` — только главная сессия координатора или его лид в папках своего направления, защиты — только Метида или её лид; везде — через запор: тесты, «принять» от argus и `--match-head-commit` на один SHA, подробно — раздел «Слияние PR»; координатор с личным в папке — mnemo-brain —
не отправляет и не сливает сам; отправляют только свой репозиторий — папки своего направления), печать в терминал (terminal: osascript, tmux
send-keys и т. п. — ввод от имени владельца), пополнение корпуса (corpus-role: `corpus add`, `channel --videos`,
`krisp`, скрипты Krisp и Диска и их ключи в Связке — ни одной роли, только через посредника; штабу корпус закрыт целиком). dev-серверы субагентам dev-* и talos в своей worktree — можно.

От **намеренного обхода и внедрённых инструкций** он не защищает: что пишет программа изнутри
(`python script.py`, `node -e`, `make`), он не видит, а свой разбор Bash мы больше не наращиваем. Настоящая
граница:

- **песочница macOS** в окнах ролей (SEC-19, SEC-26) — её собирает `pantheon domains build` в
  `~/.local/state/pantheon/settings/<направление>.json`;
- **управляемые настройки** `/Library/Application Support/ClaudeCode/managed-settings.json` (SEC-28) —
  главные запреты и хук guard, которые не перебить настройками проекта и модами.

Находку проверки безопасности по разбору Bash разбираем как «ошибка агента или граница песочницы», а не как
новый раунд поиска обходов.

## Режимы и поведение при сбое (SEC-10, SEC-29)

| Запуск | Кто вызывает | Особенность |
| --- | --- | --- |
| без аргумента | хук этого плагина | если guard уже вызывают управляемые настройки (`--managed`), хук плагина молчит — кроме Agent, Task и Skill |
| `--managed` | хук из управляемых настроек | — |
| `--strict` | хук окна роли с `onFailure: "block"` | таймаут или пропавший файл останавливают и на старом Claude Code |

**Любой сбой — выход 2 с причиной в stderr, во всех трёх режимах и в вашей сессии тоже** (metis-0094, guard 0.5.5).
Сбой — событие не JSON или не объект, исключение в проверке прав (domain, pantheon-acl, protect-config, private,
cdp-role, push, terminal, hq-telegram, chiron) или tg-secret, сбой всего скрипта, свой срок 8 с (таймаут хука —
10 с, а таймаут Claude Code вызов пропускает). Код 2 Claude Code понимает как блок на любой версии; `onFailure:
block` в hooks.json появится после обновления Claude Code до 2.1.295+. Как это сделано — обёртка `run_hook` в
`guard.py`, образец — `plugins/pantheon/hooks/agents.py`.

| Событие | Код 2 в Claude Code | Сбой guard |
| --- | --- | --- |
| PreToolUse | блок вызова, причина — агенту | выход 2 |
| PostToolUse (журнал запора слияния) | команда уже выполнена, причина — агенту | выход 2: агент узнаёт, что запись не сделана |
| Stop (подсказка nextjs) | ход не заканчивается | выход 0 и строка в журнале: код 2 крутил бы сессию без конца |

Правила-подсказки (dev-server, attribution, cdp, nextjs) при сбое пропускают к остальным проверкам: это подсказки,
а не защита. Каждый сбой — строка в
`~/.local/state/pantheon/logs/guard-failures.log` (время, режим, место, тип ошибки; без текста команды),
строка статуса показывает число сбоев за сутки.

## Ответ владельца не подделать мимо журнала (metis-0044, guard 0.5.1)

Ответ на карточке доски подтверждает только журнал ваших слов `~/.local/state/pantheon/owner-log/`: его пишут хук
answer и тик, это скрипты, guard их не видит. Сессия Claude вписать ответ не может ни одним из двух путей.

- **Доска и журнал.** В `~/ai/pantheon-view` (доска Obsidian: карточки, галочки, заметки) и в `owner-log/` не пишет
  ни одна сессия Claude: ни роль, ни субагент, ни ваша обычная сессия без роли. Доску вы правите в Obsidian сам.
  У сессии без роли запрет — по явным целям Edit, Write и Bash внутри этих двух папок. Цель, которую разбор Bash не
  вычислит, и запись в папку выше (`cp a ~/` даёт цель `~`) ей не запрещены, иначе встали бы обычные команды. Остальной
  `~/.local/state/pantheon` сессии без роли открыт, как раньше: ответа там нет.
- **Файлы задач.** `~/ai/pantheon/directions/*/tasks/` и входящие `~/ai/pantheon/inbox/tasks/` роли и любые
  субагенты, штаб тоже, меняют только командой `pantheon task` (new, set, claim). Команда не принимает поля `answer`
  и `requested`: их ставит тик из журнала. Прямая правка (Edit, Write, перенаправление, `cp`, `mv`, `rm`) — отказ.
  Запись в папку над `tasks/` целиком — тоже отказ: `cp -R`, `rsync`, `tar -C`, `unzip -d` или `cp a.md` в
  `directions/<имя>/`, в `directions/` или в `inbox/` положили бы в `tasks/` что угодно. Файл туда копируют с
  точным именем: `cp a.md directions/<имя>/a.md`. Удалить или переименовать папку направления целиком (`rm -rf`,
  `mv directions/<имя>`) роли тоже не могут: это делает ваша сессия без роли или `pantheon archive`. Можно создать новую папку направления, ещё не существующую папку
  `tasks/` и заглушку `.gitkeep` или `.keep` в ней (пустую папку тик в git не положит): ответа в них нет. Ваши сессии
  без роли файлы задач править могут: доска с pantheon 0.9.27 берёт ответ из журнала, а не из файла.
- **Почему закрыт весь `~/ai/pantheon-view`, а не только `Доска/`.** Остальная копия и так только для чтения
  (`view-sync.sh` снимает права на запись). Настройки Obsidian в `.obsidian/` копия не трогает, и их теперь тоже не
  правит ни одна сессия Claude: меняйте их в самом Obsidian.

## Окно штаба: Telegram, chiron, пульт, ключи (guard 0.5.5)

Роль окна guard берёт из переменной `PANTHEON_ROLE`: её ставит `pantheon start` в файле окна, роли его не перепишут.
В событиях фоновой сессии `agent_type` нет, а у субагента он свой, поэтому «это окно штаба» по событию не узнать.

- **hq-telegram (P0-1, metis-0060).** В окне штаба (`PANTHEON_ROLE=hq`) отказ: субагент `tg-reader`, навык
  `telegram-read` (и `плагин:telegram-read`), Bash со скриптом tg-read или демоном `tg-readd` в тексте команды. Причина:
  у Зевса личное и действия наружу, а переписка и каналы — чужой текст. Вопросы по Telegram-каналам и праву — Фемиде
  (themis-sources) через поручение. Рядом то же закрывают хук qmd-query плагина pantheon (коллекция `legal`) и
  песочница окна (`~/projects/legal-watch/cache`, `inbox`).
- **chiron (P0-2, metis-0061).** Коуч видит личное, только когда `PANTHEON_ROLE=hq`. Позвать его (Agent или Task с
  `subagent_type: chiron`) можно в окне штаба и в вашей сессии без роли; из окна другой роли и из субагента вне окна
  штаба — отказ.
- **Agent, Task и Skill при управляемых настройках.** Управляемые настройки вызывают guard только для Bash, Write,
  Edit, MultiEdit, NotebookEdit, Read, Grep, Glob и WebFetch. Поэтому эти три инструмента хук плагина проверяет и тогда,
  когда guard уже стоит в управляемых настройках. Сбой этих проверок — отказ.
- **Пульт (metis-0047).** `pantheon stop`, `resume`, `pause` и `restart` — только у привилегированных ролей, как
  `start` и `wake`. `pantheon saved` и `pantheon who` открыты всем, `pantheon jobs pause|resume` — по-прежнему.
- **Пробная сборка ролей (metis-0097).** `pantheon roles build` ролям закрыт, кроме `--out <папка> [--src <папка>]`, где
  `--out` — разобранный путь внутри временной папки (TMPDIR, /tmp); любой другой вид команды — отказ.
- **Ключи git-crypt штабу (metis-0084).** У hq и chiron из личного закрыты только ключи. Отказ — на явный путь в ключ
  или шаблон, который в него раскрывается (`ls ~/ai/pantheon/.git/*`). Поиск по папке выше (`grep -r … ~/ai/pantheon`,
  Grep по ней) проходит: ключи закрывает и песочница окна. Ролям без доступа к личному правило прежнее: `grep -r` по
  папке, где лежит `me/`, — отказ.

## Слияние PR: три режима и запор (metis-0038, guard 0.5.0; запор — P1-4, guard 0.5.4)

**Запор, коротко.** С guard 0.5.4 `gh pr merge` проходит, только если то, что проверено, — ровно то, что сливается.
Поштучного «да» владельца на PR больше нет: `--subject "[metis-NNNN] …"`, ответ окна вопросов в zeus.md, отметки
`merge-consent/` и таблицу `[merge_protect]` guard не читает. Их заменил журнал проверок
`~/.local/state/pantheon/merge-gate/records.jsonl`. Ядро защит (Д3) по-прежнему сливает только владелец кнопкой.

**Включение.** Новая схема включается строкой `[merge_client]` в policy.toml (даже пустой таблицей) — это шаг
Метиды. До этого для своих папок всё как в 0.4.7: сливают только направления из `[merge]`, в его папках, `-R` — из
`[merge_repos]`; Гермес и Афина без `[merge]` не сливают. Режим защит, запор и все проверки сбоев действуют сразу.
Внутренние папки Метиды без `[merge]` до включения закрыты. После выпуска 0.5.4 каждому сливающему направлению нужна
строка в `[merge_repos]` со всеми его репозиториями, и своими тоже: без неё запор закрывает слияние даже без `-R`.

`gh pr merge` разрешён главной сессии координатора направления (`domain-coordinator` без `agent_id`) и лиду
этого направления (metis-0054, guard 0.5.2). Лид — субагент `hephaestus-<short>` или `apollo-<short>`, где short —
имя направления папки запуска (domains.json) после первого «-»: так роли собирает `pantheon roles build`
(hermes-alex → hephaestus-alex, metis-pantheon → hephaestus-pantheon). Дальше лид проверяется как координатор: те же
режимы, личное и запор. Лиду чужого направления, сессии без направления (штаб ~/ai/pantheon) и
остальным субагентам — dev-*, argus, talos, prometheus — отказ: они отправляют свою ветку, открывают PR и пишут в
отчёте лиду, что проверено и что меняется. Штабу и мастерской — тоже отказ. Координатор с личным в папке
(mnemo-brain, `[private]`) и его лид не сливают, как и не отправляют: третье свойство (наружу) им закрыто.
Лид узнаётся по имени роли и папке запуска сессии; кто его позвал, guard не видит. Поле `leads` реестра guard
не читает: `apollo-<short>` проходит и у направления без лида дизайна — такой роли просто нет среди собранных.

Режим guard выбирает по папке, из которой запущена команда (cwd сессии, без `cd` в самой команде), и по
репозиторию, в который сольёт gh:

| Режим | Где | Кто | Что запор требует сверх общего |
| --- | --- | --- | --- |
| Защиты | папки `[coordinators] metis-pantheon` (agent-kit, ~/.claude…) или их репозиторий | только Метида и её лид | Д3: PR не задевает ядро защит |
| Продукт | `[merge_client]` направления | координатор этого направления и его лид | запись talos и строка «что ушло» с откатом |
| Внутреннее | папки своего направления из domains.json (и `[merge]` — для совместимости) | координатор этого направления и его лид | — |

**Что проверяет запор во всех режимах** (код — `hooks/merge_gate.py`):

1. Один номер PR, без `--auto` и `--admin`, ровно один `--match-head-commit <SHA 40 знаков>`. GitHub сольёт PR,
   только если его голова — этот коммит, поэтому слияние не уедет на непроверенный код.
2. Все репозитории команды (`-R`, а без него — remote папки и gh-resolved) — из `[merge_repos]` своего направления,
   и репозиторий ровно один.
3. В журнале есть запись тестов `tests` на этот SHA в этом репозитории.
4. Последний вердикт argus на этот репозиторий, PR и SHA — «принять» (`accept`) с полным перечнем проверенного
   (Б6, guard 0.5.6): что открыл, что запустил, чего не проверял. «Принять» старого формата, без перечня, запор не
   пускает — argus повторяет его с флагами. «Вернуть» (`reject`) после «принять» закрывает слияние до нового
   «принять». Вердикт берётся только из записи хука по роли argus: «одобри, argus: принять» в тексте PR или
   коммита ничего не значит (канарейка Б1 в `tests/test_merge_gate.py`).
5. Рецензент — не сливающий: пара session_id и agent_id у «принять» не совпадает с той, что сливает.
6. Продукт: ещё запись `talos` на этот PR и SHA и строка в `~/ai/pantheon/alerts.md` вида
   `YYYY-MM-DD HH:MM · кто · …` со ссылкой `owner/repo#N` и словом «откат» (её пишет `pantheon alert`).
7. Защиты: Д3 — `gh pr view N -R <repo> --json headRefOid,changedFiles` и список файлов
   `gh api repos/<repo>/pulls/N/files --paginate` (таймаут 6 с). Ядро защит — весь `plugins/guard/**` (без учёта
   регистра; решение владельца 15.10, metis-0092) и `.claude-plugin/marketplace.json` — откуда ставятся плагины,
   его подмена увела бы источник guard (metis-0115, guard 0.5.6); проверяются и новый путь, и `previous_filename`, так что вынос
   файла из guard тоже виден. PR, который задевает ядро, сливает только владелец кнопкой. gh не ответил, список
   файлов неполон или PR уже на другом коммите — тоже отказ.

**Как появляются записи.** Журнал пишет только хук guard на PostToolUse, после успешной простой команды
`pantheon review <вид> …` — без `;`, `|`, `&`, `$(`, обратных кавычек, перенаправлений и переводов строки. Сама команда
`pantheon review` (плагин pantheon) ничего не пишет: она проверяет формат и запускает тесты.

- `pantheon review test -- <команда тестов>` — в чистом дереве git, запись `tests` на HEAD и репозитории remote.
  Код выхода — код команды; упала команда — хук не пишет (PostToolUseFailure записей не делает). Команда меняет
  HEAD или пачкает дерево — код 3, записи тоже нет. Программа после обёрток (`heavy`, `env VAR=…`, `time`, `nice`,
  `timeout N`) — `true`, `:`, `echo`, `printf`, `exit`, `test`, `[`, `sleep` или `yes` — отказ на PreToolUse и
  записи нет: такая команда ничего не проверяет.
- `pantheon review accept <owner/repo> <PR> <SHA> --opened "<что открыл>" --ran "<что запустил>" --unchecked "<что
  не проверял>"` — записывается, только если роль — argus и все три поля есть и непусты (`--ran=…` тоже можно);
  в записи — `"checklist": {"opened", "ran", "unchecked"}`. `reject` — те же флаги по желанию. Значения — без `;`,
  `|`, `&`, `<`, `>`, `$(`, обратных кавычек и переводов строки (правило простой команды); кавычки и пробелы внутри
  поля можно.
- `pantheon review talos <owner/repo> <PR> <SHA>` — только если роль — talos.
- `pantheon review status [<owner/repo> <PR>]` — показать записи.

Фоновая команда записи не даёт: для неё PostToolUse приходит при запуске, а не по итогу, а PostToolUseFailure не
приходит вовсе. Поэтому хук не пишет, если во входе `run_in_background`, в ответе `backgroundTaskId` или ответ — не
словарь.

Не той роли или с плохими аргументами `pantheon review accept|reject|talos` получает отказ сразу на PreToolUse:
иначе команда прошла бы, а записи не появилось. Так же сразу отказ для `pantheon review test|accept|reject|talos` в
фоне и не простой командой. argus ещё запрещены `git commit`, `merge`, `rebase`, `cherry-pick`,
`am`, `revert`, `pull`, `commit-tree`: рецензент не меняет то, что проверяет.

**Почему журнал не подделать ошибкой агента.** Папку `~/.local/state/pantheon/` роли не пишут (pantheon-acl), а
вид записи и роль автора хук берёт из события Claude Code (`agent_type`), а не из текста команды. Файл журнала —
0600 в папке 0700, только дозапись, без перехода по симлинку. Папка журнала или файл — симлинк, файл не читается —
слияние закрыто. Битые строки при чтении пропускаются. В режимах `--strict` и `--managed` записи не делаются:
журнал пишет только хук плагина. Выключатель — `GUARD_OFF=push`.

**Защиты узнаются по пути и по репозиторию.** gh сливает в репозиторий из git remote папки, а не в папку. Поэтому
guard читает `git remote -v` у каждой папки защит с `.git` и сверяет с репозиторием команды: значением `-R`, а без
него — remote папки cwd и `remote.<имя>.gh-resolved` (gh repo set-default, кроме «base»). Клон, форк с
set-default, worktree или симлинк agent-kit в любой папке — тоже защиты. Сверка идёт по owner/repo без хоста:
псевдоним ssh (`git@gh-work:latark/agent-kit`) gh понимает как github.com. Проверка идёт
раньше реестра: если domains.json по ошибке отдаст agent-kit другому направлению, слить его сможет только Метида.
Реестр для слияния — только `~/.local/state/pantheon/domains.json`, без отката на старый
`~/.claude/hooks/domains.json`: там направления шире.

**Своя папка — по самому длинному корню.** Владелец cwd — направление с самым длинным совпавшим корнем в
domains.json, и оно должно совпасть с направлением папки запуска. Корень вроде «~/projects» у одного направления
не открывает папку другого внутри.

**Любой сбой — отказ.** Нет policy.toml (или Python без tomllib), нет непустого списка `[coordinators]
metis-pantheon`, `[private]` или domains.json не разобрать, git не ответил, у папки защит с `.git` не читается
remote, cwd не репозиторий или без remote, журнал проверок не читается, gh не ответил — слияние закрыто.

**Пределы.**

- guard — хук PreToolUse: он проверяет состояние в момент вызова. Что изменится после его «можно» и до запуска gh
  (подмена симлинка cwd, правка git config), он не видит. Это уже намеренный обход, граница — песочница окна.
- guard не проверяет, правдива ли строка «что ушло» в alerts.md и перечень в «принять» argus, и что команда
  тестов — настоящие тесты. С 0.5.6 он ловит только ошибку: пустую программу после обёрток (`true`, `echo ok`,
  `heavy :`, `env X=1 timeout 60 sleep 1`). Обёртку вроде `sh -c true` или `python3 -c pass` он не ловит — это уже
  обход, разбор ради него не наращиваем. Настоящесть тестов — обязанность роли и предмет проверки argus: он пишет
  в `--ran`, что запустил сам.
- Список файлов сверяется с `changedFiles`; если gh отдал неполный список (предел API — 3000 файлов), PR защит закрыт.
- Ядро — весь `plugins/guard/**`, casefold; файлы из `pulls/N/files` с `previous_filename`. Д3 опирается на то,
  что `guard.py` зовёт `merge_gate.py`; правку `guard.py`, которая это ломает, Д3 тоже останавливает: `guard.py` — ядро.
- «Один номер PR» — на один вызов `gh pr merge`: `gh pr merge 5 … && gh pr merge 6 …` пройдёт двумя слияниями,
  каждое — со своими записями. Счётчика на всю команду нет, разбор Bash не наращиваем.

Везде закрыто: `--admin` (и `--admin=…`), `--auto`, `GH_REPO`/`GH_HOST`, `cd` в команде, PR ссылкой или `$N` вместо
номера, `-R` не из `[merge_repos]` своего направления, `gh api` с записью, push в main и master.

## Управляемые настройки (SEC-28)

Ставятся один раз на Mac, в вашем терминале (нужен пароль):

    sudo mkdir -p "/Library/Application Support/ClaudeCode"
    sudo install -m 644 ~/.claude/plugins/marketplaces/agent-kit/plugins/guard/managed-settings.json \
      "/Library/Application Support/ClaudeCode/managed-settings.json"

Файл — `managed-settings.json` рядом с этим README: запреты (ключи в Связке, `.env`, разрушительный git,
`rm -rf`, terminal-notifier) и хук guard из клона маркетплейса. Обновить — та же команда после обновления
маркетплейса. Проверка: в папке с `.claude/settings.json`, где разрешено `Bash(git clean *)`, команда
`git clean -n` всё равно получает отказ.

## Данные и выключатель

- `~/.local/state/pantheon/domains.json` — карта направлений, собирает `pantheon domains build` из
  `~/ai/pantheon/directions.toml`;
- `~/.claude/pantheon/policy.toml` — привилегии (кто metis-pantheon и mnemo-brain, доступ к личному, `[merge_repos]`),
  образец — `policy.example.toml`, правит только metis-pantheon;
- `~/.local/state/pantheon/merge-gate/records.jsonl` — журнал проверок запора слияния, пишет только хук guard
  (PostToolUse), смотреть — `pantheon review status`;
- выключить правило: `GUARD_OFF=dev-server,nextjs` в `env` файла settings.json (`push` выключает и запись журнала запора).
