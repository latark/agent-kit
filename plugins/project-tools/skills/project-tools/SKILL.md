# Инструменты проекта

Что подключать, решает карта стеков `stacks.json` плагина project-tools, а не ты: команда добавляет только её записи.
Руками не дописывай серверы в `.mcp.json` и одобрения в `.claude/settings*.json` — это делает команда.

1. Посмотри, чего не хватает: `project-tools check` (из корня проекта или `--dir <папка>`). Код выхода 3 —
   есть что сделать, 0 — всё по карте, 2 — файл настроек битый или стоит ссылкой (ничего не трогай, покажи ошибку
   владельцу).
   Раздел «Серверы MCP» — подключается ли сервер на самом деле (metis-1153): HTTP-сервер, одобренный на этом Mac
   (отпечаток записи от `project-tools apply` совпал; изменённый или без отпечатка — «не проверяю»), проверяется запросами initialize и tools/list («+ подключается, инструментов N», «! не подключается: причина»).
   «? не проверен — нужен вход» — OAuth: вход делает владелец в окне (`/mcp` → Authenticate), сам не входи.
   stdio-серверы не запускаются («·»). Без сети — `--no-net`; код выхода раздел не меняет.
   Координатору направления этот итог приходит сам: плановый проход проверяет папку, когда в ней меняется
   `.mcp.json` или одобрение, и кладёт файл во `inbox/` направления (metis-1047) — владельцу передавать не нужно.
2. Покажи владельцу строки «Нужно» и заметки «·» как есть, коротко: что появится и зачем.
3. Подключай, только если ты в сессии владельца без роли Пантеона и он согласен (просьба «настрой проект» —
   уже согласие): `project-tools apply`. Отличие готовой записи от карты меняй только по его слову:
   `project-tools apply --update <имя>`.
4. Владелец сказал «не надо» — `project-tools skip <имя>…`: сервер не запустится, подсказка о нём замолчит.
5. После apply скажи: серверы заработают в новой сессии; общие файлы (`.mcp.json`, `.claude/settings.json`,
   `.codex/config.toml`) — для коммита, `settings.local.json` личный и в git не идёт. Одобрение сервера
   (`enabledMcpjsonServers`) лежит в `.claude/settings.json` — коммить его в том же PR, что `.mcp.json`: после
   слияния сервер одобрен без вопроса в окнах ролей и на других Mac. Сам не коммить без просьбы.

## Предупреждение «⚠ изменились одобренные серверы»

Одобрение в Claude Code — по имени: после `git pull` под тем же именем могла прийти другая команда, и она уже
запущена. Сразу скажи владельцу, покажи `project-tools check` и `git log -p .mcp.json`, инструменты этих серверов
не вызывай. Его ответ: «это моё» — `project-tools apply --accept <имя>`; «не моё» — `project-tools skip <имя>` и
откат записи в `.mcp.json`.

## В окне роли Пантеона (координатор, лид, разработчик)

`apply` и `skip` там не сработают: песочница Claude Code и guard (правило protect-config) запрещают ролям запись в
`.mcp.json` и `.claude/settings*.json`. Обходить запрет другой командой нельзя. Запусти `project-tools check` и
поставь владельцу вопрос на доске: что подключить, зачем, готовая команда `project-tools apply --dir <папка>`.

## Нового инструмента нет в карте

Не подключай его мимо карты. Опиши находку (что, для какого стека, ссылка на пакет) — metis-pantheon добавит
запись в `stacks.json` после «да» владельца. Свежие версии закреплённых пакетов: `project-tools outdated`.
