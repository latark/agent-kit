# agent-kit

Маркетплейс плагинов Claude Code для системы агентов «Пантеон». Общие части собираются здесь сразу,
поэтому на другой установке работает то же, что у владельца; роли армии, хранилище знаний и ключи у каждого свои.
Приватный репозиторий `latark/agent-kit`; ведёт его metis-pantheon (изменения — после «да» владельца).

| Плагин | Что делает | Состояние |
| --- | --- | --- |
| `guard` | Правила, которые Claude Code проверяет сам: dev-server, attribution, cdp, tg-secret, nextjs, domain, pantheon-acl, protect-config, private, cdp-role, push, terminal; модель угроз и режимы — `plugins/guard/README.md` | работает с 14.10 (шаг 0.4); управляемые настройки — шаг 0.6, ставятся через `sudo` |
| `pantheon` | Планировщик `pantheon-tick` (launchd, раз в 60 с), команда `pantheon`, копия `~/ai/pantheon-view` для Obsidian, задачи и доска владельца, коммит `~/ai/pantheon`, настройки окон ролей с песочницей и строгим guard, сверка карты решений; хуки контекста (подсказка «пора очистить», продолжение после `/clear`, файл состояния после сжатия) и журнал ваших слов owner-log; запуск сессий (`pantheon start`, `wake`; откуда запуск, берётся из `--from`, а без него из окна: `PANTHEON_ROLE=hq` — zeus, другая роль — tick, без роли — вы, и в окне роли явный `--from` должен совпадать с origin окна (hq — zeus, другая роль — tick), иное, в том числе `--from owner`, — отказ, код 2; zeus без вашего слова в окне Зевса — отказ, код 2, и у `--at` при постановке; `start` пишет замер загрузки Mac в `capacity.jsonl`, красный замер или «нет сигнала» (своп и давление не прочитаны) без вашего слова — код 5 «отложено», не сбой: самозапуск и разовый запуск повторяются; `wake` пишет строку замера и красной зоной не откладывает, кроме `wake hestia` из окна роли (не hq): со словом в красной зоне — код 5, без слова — код 2; `wake <имя> "задание"` из окна роли (задан `PANTHEON_ROLE`) без вашего слова в окне Зевса за 15 мин — отказ, код 2, сессия не поднимается (строка замера «refused»), без задания `wake <имя>` будит с «продолжай» и слова не требует; дежурный зовёт дочерний `pantheon start` без роли окна, поэтому `pantheon watch`, запущенный из окна Зевса, самозапуск не ломает; разовый запуск `start --at` исполняется по правилам планового прохода: в красной зоне ждёт, слово при постановке не переносится), сборка ролей (`pantheon roles build`), заранее разрешённое (`pantheon approve`), обёртка `heavy`, Stop-хук разработчика; дежурный без модели (`pantheon watch`: сессии, swap, worktree, версия Claude Code, паузы, самозапуск по вашим решениям, журналы ваших слов), пересмотры, остановка и пауза, технический перезапуск, продолжение сессий `claude respawn` с текстом через хук | работает с 14.10 (шаг 0.4); хуки — с шага 1.1; роли и запуск — с шага 1.2; дежурный и перезапуск — с 0.10.0 (шаг 1.4) |
| `project-tools` | Инструменты проекта по карте стеков `stacks.json`: MCP-серверы (next-devtools, chrome-devtools, shadcn) — в `.mcp.json` проекта с одобрением, плагины (Supabase) — в настройки проекта, блок для Codex; команда `project-tools` (check, apply, skip, outdated), навык, подсказка при старте сессии; отпечатки одобренных записей — предупреждение о подмене после `git pull` | с 14.10 (шаг 0.7) |

## Где что лежит

- `plugins/guard/hooks/guard.py` — все правила; шапка файла перечисляет их и выключатель `GUARD_OFF`.
  Данные: `~/.local/state/pantheon/domains.json` (собирает `pantheon domains build` из
  `~/ai/pantheon/directions.toml`) и `~/.claude/pantheon/policy.toml` — привилегии (образец —
  `plugins/guard/policy.example.toml`), правит только metis-pantheon.
- `plugins/pantheon/lib/pantheon.py` — планировщик и команда; `pantheon help` — список команд.
  Задачи — `~/ai/pantheon/schedule.toml`, метки и журналы запусков — `~/.local/state/pantheon/` (свои у каждого Mac).
- Требуется Python 3.11+ (`tomllib`). Системный `/usr/bin/python3` на macOS — 3.9, он не подходит; `bin/pantheon` и
  `bin/pantheon-tick` сами ищут 3.11+ (`lib/find-python.sh`): `PANTHEON_PYTHON`, затем `python = "…"` из
  `STATE/config.toml` (его пишет `pantheon-setup`), затем `python3` из PATH, `python3.14`…`3.11`, Homebrew, python.org.
  Не нашли — строка «нужен Python 3.11+» и код 1, у планового прохода ещё строка в `alerts.md` не чаще раза в сутки. Новой установке
  Python ставит `pantheon-setup` (uv, Python 3.14); вручную — `brew install python@3.14`. Хуки guard и pantheon тоже
  идут на 3.11+ (metis-0571): их запускает `hooks/python.sh` — ищет `python3.14`…`python3.11` в `/opt/homebrew/bin`,
  `/usr/local/bin`, python.org и PATH, затем `python3` из PATH с проверкой версии. Не нашёл — PreToolUse
  останавливает действие с кодом 2 и строкой «нужен Python 3.11+», остальные хуки молчат (код 0). guard.py, запущенный
  старым `python3 guard.py` (managed settings до переустановки, старые настройки окон), на 3.9 сам перезапускается
  через `hooks/python.sh`. `pantheon infra-check` показывает строки «Python установки» и «запускатель хуков».
- Установка для нового человека (macOS): `plugins/pantheon/bin/pantheon-setup` из клона agent-kit, одной командой.
  Загрузчик на bash до всего проверяет, что это macOS, что `~/ai/pantheon` (`PANTHEON_HOME`) нет или он пуст, что `claude`
  на PATH и клон — репозиторий; при отказе ничего не ставит. Дальше ставит uv (`UV_NO_MODIFY_PATH=1`, профили
  оболочки не правит) и Python 3.14, уже стоящие Python не трогает, и передаёт дело `lib/setup.py`. Он идёт по шагам,
  у каждого итог «ок / пропуск / не вышло»: путь Python в `config.toml`; маркетплейс и плагины guard, pantheon,
  project-tools; пустой `~/ai/pantheon` из `plugins/pantheon/template/pantheon/` с `git init`; `pantheon install`;
  `pantheon roles build`; вход git в GitHub через gh (`gh auth setup-git` — только после явного «да»);
  резервная копия (ниже); terminal-notifier; проверка личных следов (`scripts/check-traces.py` по файлам установщика и собранным ролям, маркеры —
  `--markers ФАЙЛ` или `PANTHEON_TRACE_MARKERS`, нет файла — пропуск); Codex (`--codex`, `--no-codex`, без флагов —
  вопрос, по умолчанию нет). До push — `pantheon traces` (та же проверка, что CI check-traces, по файлам репозитория; маркеры —
  `--markers ФАЙЛ`, `PANTHEON_TRACE_MARKERS` или `~/.config/pantheon/trace-markers.txt`; нет файла — отказ, код 2) и
  `pantheon traces install-hook` (pre-push в репозитории, без молчаливой замены чужого хука). `pantheon-setup --add codex` — только шаг Codex на готовой установке. К системе
  `setup.py` ходит через `lib/platform_macos.py` (Homebrew, launchd, sandbox-exec, Связка ключей, текст про
  уведомления). Тест — `plugins/pantheon/tests/test_setup.py`, все внешние программы в нём — заглушки.
- Резервная копия (metis-0476): шаг установщика после входа в GitHub и `pantheon-setup --add backup` на готовой
  установке. Идёт, только если gh вошёл и стоит git-crypt (`brew install git-crypt`), и только после «да» на вопрос;
  иначе строка «копии нет: при потере Mac данные пропадут». Уже задан `origin` — пропуск, второй репозиторий не
  заводится. Порядок: `git-crypt init` → ключ (`git-crypt export-key` во временный файл в `$TMPDIR`, сразу удаляется)
  base64 в Связку ключей через stdin (`security -i`, ключа нет в аргументах процесса; запись после добавления проверяется), служба `pantheon-git-crypt` (запись уже есть — отказ, старый ключ не перезаписывается) →
  `.gitattributes` (`* filter=git-crypt diff=git-crypt`, `.gitattributes` и `.gitignore` открыты) → снимок: коммит
  без родителей, ветка переставляется на него, прежняя история остаётся локально в `refs/pantheon/pre-backup`, при повторе после сбоя — `pre-backup-2` и т. д., коммиты между попытками не теряются (иначе
  старые коммиты ушли бы в GitHub открытыми; об этом прямо говорит вопрос до «да») → проверка, что каждый файл снимка начинается с заголовка git-crypt →
  только потом `gh repo create <имя> --private` (`--backup-name ИМЯ`, по умолчанию `pantheon-hq`), `origin` и
  `git push -u`. Сбой до GitHub ничего снаружи не создаёт. Связка ключей не уходит в iCloud, поэтому установщик
  просит сохранить ключ ещё и вне Mac (менеджер паролей; показать — `security find-generic-password -s
  pantheon-git-crypt -w`). Вернуть на другом Mac, положив ключ в его Связку под той же службой: `git clone <адрес> ~/ai/pantheon`, затем в этой папке
  `security find-generic-password -s pantheon-git-crypt -w | base64 -d > "$TMPDIR/k" && git-crypt unlock "$TMPDIR/k"`
  и `rm "$TMPDIR/k"`.
- Настройки человека — `STATE/config.toml` (`~/.local/state/pantheon/`, свои у каждого Mac): `python`, таблица
  `[executors] set` (Claude всегда, Codex — дополнение) и `[codex]` (состояние проверки). Читает и пишет только
  `lib/pconfig.py` (`load`, `update`).
- Исполнители (`lib/executors.py`): `pantheon executors` — набор и состояние, `check` — проверка Codex (на PATH, вход,
  hello-проба), `--add codex`, `--remove codex`, `pick <id задачи>` — кто пишет задачу. `pantheon exec codex <папка
  worktree> <файл поручения>` — запуск Codex в worktree; коды выхода: 0 — коммит есть, 1 — отказ (ошибка хода,
  защищённые пути, нет изменений), 2 — неверный вызов или worktree не чистый (игнорируемое не в счёт), 3 — Codex
  недоступен (задачу на dev-*), 4 — занят.
- Лёгкий плановый проход: `pantheon` идёт модулем через `lib/run.py` (байт-код в `lib/__pycache__`, при read-only папке молча
  без кэша), `--help` ~34 мс вместо ~62. Задачи `view --quiet`, `board`, `sync-answers`, `agents` плановый проход пропускает, если
  их входы (отпечаток stat, таблица входов — `TICK_SKIP` в `lib/pantheon.py`) не менялись с прошлого удачного прогона;
  не реже раза в 15 минут они идут в любом случае, ручной вызов и `run-job` — всегда. Пропуски — `tick-skipped.json`.
- Недельный потолок владельца (с 0.11.100, metis-0403; формат — шапка `lib/night.py`): `[limits.owner_cap]` в
  `schedule.toml` (`pct`, `decision`, срок `until`/`since`, старый дневной `date`). Неделя ≥ `pct` — отказ самозапуску,
  `wake` и `respawn` дежурного днём и ночью и новым субагентам из окон координаторов, мастерской и Пританея (хук PreToolUse
  `Agent|Task` → `pantheon night agent-gate`); зоны и ночь потолок не снимает. С metis-0444 он же держит ручные
  `pantheon start` и `wake` (все виды, кроме `start zeus` и Гестии — `wake hestia`, решение владельца 29.10), запуск по вашему ответу в окне вопросов (отказ, код 2) и
  задачи `claude -p` планового прохода (ждут, срок не сдвигается). Сверх потолка — только из вашего терминала флагом `--over-cap`.
  Одна тревога и одна карточка Зевсу на неделю и `pct`; `pantheon night status` показывает потолок и запас.
- Запуск без СБ ([sb-simplify] п. 5 и 10, metis-0523, metis-0564). Окна по ответу владельца: вопрос Зевса в окне
  вопросов строго по шаблону `pantheon launch-question <id> запустить|перезапустить|вернуть <направление>` и выбор
  «Да — <глагол> <имя>» плановый проход исполняет сам (`word_launch` в `lib/watch.py`); любое отличие, заметка или свой
  текст — отказ. «Остановлено вами» снимает только «Да — вернуть <имя>» (затем окно поднимается) или `pantheon resume`;
  запустить и перезапустить остановленное не трогают. Каждое поручение — строка
  `word-launch` в `logs/start.log` и строка в `alerts.md`; запись исполняется один раз, не старше 12 ч. Своп и давление
  памяти запуск не откладывают: только предупреждение в stderr и тревога раз в день. Окно Зевса пишет только в
  `STATE/hq-rw/locks` (замки имён сессий `start-*`, `wake`) и `STATE/hq-rw/autostart-reset`; замки прохода — в
  `STATE/locks`, куда окно не пишет. Файл в `hq-rw` открывается с `O_NOFOLLOW|O_NONBLOCK` и проверкой `fstat`
  (обычный файл, одна ссылка, свой владелец); ссылка, FIFO или папка на месте записи — отказ блокировки с предупреждением,
  а не падение start и прохода. Ждущая блокировка там ждёт не больше 60 с; `pantheon stop` без блокировки вслепую не
  останавливает: ставит метку «остановлено вами» и выходит с кодом 1 — повторить. Ночь (вариант Б, 28.10): фиксированного вопроса в 22:00 нет, ночь открывается только ответом «Да — ночь
  <дата>» на вопрос `pantheon night ask <id> <направление>` о ночной пачке; в вопросе — путь и sha256 пачки, проход
  сверяет ответ дословно и sha256 файла, изменённая пачка не идёт. Без такого ответа ночью новое не запускается.
  Самозапуск не отдаёт координатору задачу, которую ведёт другая сессия (`owner` вне направления и его команды).
- Размер песочницы окна (с 0.11.17): Seatbelt не собирает профиль больше 64 КБ, и тогда Bash окна не запускается
  совсем. Поэтому `sandbox_build` считает байты путей песочницы окна. Выше предела — 48 КБ, переменная
  `PANTHEON_SANDBOX_LIMIT` — окно не пересобирается: остаётся прежний файл, приходит одна тревога «песочница окна …».
  Пританей закрывает чужие папки в `/tmp/claude-<uid>` и `~/.claude/projects` шаблонами по префиксам, а не перечислением,
  поэтому мусор тестов список не раздувает. Корень `/tmp/claude-<uid>` и папки в нём на `tmp` открыты: это `$TMPDIR`
  песочницы, в нём временные файлы heredoc и mktemp и временные папки `mktemp -d` и `tempfile`.
- Сокеты окон ([sb-simplify], 27.10): окна направлений и мастерская получают `allowUnixSockets` — ровно свой кэш
  `~/Library/Caches/pantheon-sandbox/<окно>` (tsx IPC, профиль Chromium), и `PANTHEON_TMP` — папку `tmp` в нём.
  `TMPDIR` песочница ставит сама (`/tmp/claude-<uid>`, env окна его не перебивает, сокет там запрещён), поэтому тесты с
  сокетами запускают `TMPDIR=$PANTHEON_TMP …`. Местных портов (`allowLocalBinding`) нет ни у одного окна: в Claude Code
  2.1.311 он открывает весь localhost — и местный прокси (выход наружу мимо `allowedDomains`), и 9222 браузера. Пароль
  демона CDP (`~/.config/cdp-daemon`) окнам закрыт на чтение — песочницей и правилом Read. Окна задач расписания,
  Гестии и Пританея сокетов не получают.
- Ручные разрешения окнам ([sb-simplify] п. 6): `~/.claude/pantheon/grants.toml` — правит владелец или Метида
  (protect-config), выпуск его не стирает. Запись `[[grant]]`: `window` (имя окна или `"*"`), `until = "ГГГГ-ММ-ДД"`
  (включительно, обязателен), `why`, и списки `allow` (permissions.allow), `write` (allowWrite песочницы), `domains`
  (allowedDomains). Других ключей нет; запись в `~/.claude`, `~/.config`, `~/.ssh`, `~/.gnupg`, `~/Library`,
  `~/.local/bin` и файлы оболочки не даётся. Ошибка — запись не применяется, тревога `grants-bad`. Сборка окна
  добавляет разрешения в силе и обновляет файлы запущенных сессий этого окна (`settings/run/`, по `PANTHEON_WINDOW`).
  Плановый проход пересобирает окна после правки файла и к сроку: истёкшее снимается само, тревога одна на разрешение.
  Образец:

  ```toml
  [[grant]]
  window = "athena-shop"
  until = "2026-11-10"
  why = "e2e на Playwright до PR #42"
  allow = ["Bash(pnpm test:e2e *)"]
  domains = ["cdn.playwright.dev"]
  ```

- Окна ролей (с 0.11.14, `sandbox_build`): мастерской и Пританею правила слияния нет. Окну координатора направления
  `allow` для `gh pr merge` не даётся совсем (`COORDINATOR_ALLOW` пуст, metis-0137): слияние без вопроса пускает только
  правило autoMode «Pantheon Gated Merge» (шлюз слияния, ниже), а каждое слияние дополнительно проверяет guard: главная
  сессия domain-coordinator или лид её направления (`hephaestus-*`, `apollo-*`; metis-0054), свои папки, без `--admin`
  и `--auto`.
  Проверка проектных allow (metis-0137): `.claude/settings.json` проекта сливается с `--settings` окна, а правило allow
  срабатывает раньше классификатора auto. Поэтому `Bash(gh *)` в `.claude/settings.json` или `settings.local.json`
  папки запуска возвращало бы слияние `--admin`/`--auto` мимо шлюза. `sandbox_build` проверяет оба файла: правило
  `Bash`, `Bash(*)` или `Bash(<шаблон>)`, где начало шаблона до первой `*` — начало `gh pr merge` (`gh *`, `gh pr *`,
  `g*`) или само начинается с `gh pr merge` (`gh pr merge --admin *`, точное `gh pr merge 32`), а также старая форма
  `:*`. Пробелы схлопываются, регистр не важен, ведущие `VAR=значение` снимаются, путь к программе сводится к имени
  (`/opt/homebrew/bin/gh *` — это `gh *`). Обёртки, пускающие любую команду, снимаются с начала шаблона, и остаток
  проверяется так же: `env` с флагами и `VAR=`, `command`, `xargs` с флагами, `eval`, `bash|sh|zsh -c` с кавычкой.
  Поэтому ловятся `env *`, `/usr/bin/env -i *`, `bash -c *`, `bash *`, `command /opt/homebrew/bin/gh *`. Обёртка без
  `*` и без команды после неё безопасна: `env`, `command -v gh`; запуск своего скрипта `bash ./scripts/test.sh *` —
  тоже. Не ловятся свои скрипты-обёртки (`./run.sh *`), `sudo`, `nohup`, `timeout`, `exec gh *`, `time gh *`,
  `nice gh *`: граница — песочница и guard.
  При таком правиле окно направления не собирается, прежние файлы
  окна и запуска (`settings/run/<имя>.json`, его берёт `claude respawn`) убираются, в stderr строка с файлом и
  правилом (убрать правило или сузить до `gh pr view *`, `gh pr checks *`), плюс тревога. `pantheon check` и

  таймаут файла и SIGTERM/HUP/INT гасят группы файлов; код не 0 при падении, таймауте, 0 файлов и коде 0 без
  строки итога. `--affected` (metis-0451) — только тесты, связанные с изменёнными от `origin/main` (или `--base`)
  файлами, по карте `scripts/affected-map.json`: правка общего файла (lib/pantheon.py, hooks/python.sh, сам раннер,
  карта), файл вне карты, ошибка git — весь набор; ничего не затронуто — код 3 «нечего гонять». Шлюз и выпуск гоняют
  полный набор. Не macOS (CI на Linux): файлы из `SKIP_NOT_MAC` не идут и печатаются строкой `skip … пропущено`
  (отдельное число в итоге), команд ioreg, pmset, scutil файлы тестов получают как заглушки. Подробности — в шапке
  скрипта.
- `plugins/pantheon/scripts/affected-map.py` — строит карту для `--affected` прогоном всех тестов: каждый файл тестов
  в своей копии репозитория с метками, которые записывают, какие файлы он загрузил, открыл, запустил или скопировал
  (около 8 мин при трёх воркерах). В карте — sha256 каждого файла тестов: раннер находит файлы, изменённые после
  сборки, и гонит их при любом изменении (их связи по карте могли устареть); таких 8 и больше — весь набор с
  причиной в выводе. Карту строят заново, когда таких файлов набралось; то, что устаревшая карта пропустила, ловит
  полный прогон на main.
- Замеры вне окна (metis-0537): в окне роли `sysctl` памяти даёт EPERM, `claude -p` без сети не работает, поэтому замеры
  снимает плановый проход (`probes_tick` в `lib/pantheon.py`, каждый проход) и пишет `STATE/probes.json`: `mem` — своп, давление,
  свободно %; `capacity_probe` и `_memory_pressure` в окне берут из файла то, что сами не прочитали, если замер не старше 10 минут;
  старый, битый или отсутствующий файл — «не прочитано», как раньше. Замер `/context` (`claude -p /context`, стоит лимита)
  по умолчанию выключен: включается файлом `STATE/probe-context` (внутри число часов между замерами, пусто — 6), идёт отдельным
  процессом, результат — раздел `context` того же файла. `pantheon probes [show|measure|context]` — посмотреть или снять вручную.
- `plugins/pantheon/scripts/baseline.py` — замер «как сейчас» по git и транскриптам (ORD-06); правила подсчёта — в шапке.
- `plugins/pantheon/scripts/config-check.py` — проверка правок `~/.claude` для `sync.sh`: код и подозрительное — в
  карантин с объяснением на доске, остальное уходит само (SEC-15). Исключение (metis-0209): файл, побайтно равный
  файлу `plugins/pantheon` или `plugins/guard` в вершине `refs/remotes/origin/main` клона agent-kit
  (`~/.claude/plugins/marketplaces/agent-kit`), проходит без карточки, если эту вершину или голову PR (второй родитель
  merge-коммита; первый не доверен) слил владелец (SHA в `logs/merge.jsonl` с событием `merged` или в `owner-log/merge-approve.log`, репозиторий ровно `latark/agent-kit`). Клон мелкий (depth 1), но id
  родителей есть в самом коммите: слияние `--merge` кладёт голову PR вторым родителем. Вершина — коммит выпуска
  workflow release (metis-0512) с одним родителем, которого слил владелец, — тоже доверена, если меняет только строки
  `version` в `plugins/*/.claude-plugin/plugin.json` и `.claude-plugin/releases.json`: доверие по содержимому, не по
  автору. Объект родителя в мелком клоне догружается `git fetch --depth 2 origin <вершина>`; без сети — карточки как
  раньше. Только текущая вершина —
  откат файла к старому выпуску даёт карточку. Путь сверяется целиком от корня плагина (`hooks/guard.py` —
  `plugins/guard/hooks/guard.py`), файлы `tests/` не доверены, ключ в тексте флаг сохраняет. Доверено всё дерево вершины main, в том числе не-ядро, слитое через шлюз без Touch ID.
  Слитое иначе, чем через
  Touch ID `pantheon merge`, этот путь не видит — там карточка как раньше.
- `plugins/guard/managed-settings.json` — управляемые настройки (SEC-28), ставятся через `sudo` (README guard).
- `plugins/project-tools/stacks.json` — карта стеков (признак → что подключить); `plugins/project-tools/lib/project_tools.py`
  — команда `project-tools`. Пишет только записи из карты; в окнах ролей запись в `.mcp.json` и `.claude/settings*.json`
  запрещена песочницей и guard — там только `check`.
