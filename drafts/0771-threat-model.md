# metis-0771 — как окно hq может прочитать проект направления

Это модель угроз задачи metis-0771. Окно hq (Зевс) не должно делать работу направлений само.

## Что закрываем

Закрываются папки проектов направлений из `domains.json`. Не закрываются:

- `metis-pantheon` (agent-kit);
- направления с `coordinator = false` (`hq_led`): их ведёт сам Пританей;
- папки внутри `~/ai` и папки, которые содержат `~/ai` или открытую папку.

Внутри закрытой папки открыты:

- `README.md` и `AGENTS.md` в корне;
- `.git`, чтобы работали `git log` и `rev-parse`.

guard защищает от ошибки агента, а не от намеренного обхода. Граница — песочница (README guard).

## Остатки

- **`git status` из hq не пройдёт — принятый остаток.** Песочница закрывает чтение рабочих файлов, а git их читает.
  Решение Зевса 03.11 20:2x, вариант А: `git status` штабу не нужен, остаются `git log` и `gh pr view/checks`;
  отдельной команды вне песочницы не делаем.
- **Тайна в `.git` проекта.** Если в песочнице есть `denyRead` на `<проект>/.git/config` (ключ), `.git` не открывается.
  Тогда `git log` этого проекта из hq не идёт, как и до правки.
- **Проект закрыт целиком.** `allowRead` сильнее `denyRead`, поэтому исключения (`.git`, README.md, AGENTS.md) не
  ставятся, если прежний запрет (`[hq].closed_dirs`, личное) закрывает их или папку выше, в том числе шаблоном.
  Иначе исключение открыло бы то, что закрыто намеренно. Тест — test_sandbox_size «0771: closed_dirs …».

## Запуск окна координатора

`pantheon start <имя>` без других аргументов в окне hq кладёт заявку в `STATE/hq-rw/start-req/<имя>.req`.

| # | Угроза | Чем закрыта | Тест |
|---|---|---|---|
| 15 | Имя не из реестра | отказ при заявке (код 2) и при разборе | test_start_request: «чужое имя» |
| 16 | Лишние аргументы или флаги | metis-1009: текст поручения — файлом во входящие направления (O_EXCL, O_NOFOLLOW, до 100 000 байт в UTF-8) и обычная заявка без текста; текст, начатый с «-», — такое же поручение, а отдельное слово вида флага, которого start не знает (`--force`, `-v`), — отказ (код 2) одной строкой (metis-1013); `--restart`, `--over-cap` — прежний путь через start_gate, без записи STATE/settings/run — отказ одной строкой; `--at-cancel` — строка `cancel` в заявке, её гасит проход; уже исполненный запуск отмена не трогает (итог запуска остаётся) | «16 (metis-1009)», «16 (Д3)», «16 (m6)», «cancel (Д2)», test_hq_commands |
| 17 | Подложенный файл заявки: лишние ключи, чужое имя, ссылка | разбор вне окна: O_NOFOLLOW, обычный файл, ключи, имя = имя файла | «подложенная заявка» |
| 18 | Заявка на `hq_led` | отказ: координатора нет | «hq_led» |

Корректная заявка становится разовым запуском: `oneshot`, `by=zeus-request`. Его исполняет проход по своим правилам —
занятость, недельный шлюз, один запуск за проход.
