# guard

Правила, которые Claude Code проверяет сам, а не на память модели. Хук PreToolUse (Bash, Write, Edit, MultiEdit,
NotebookEdit, Read, Grep, Glob, WebFetch) и Stop; весь код — `hooks/guard.py`, его шапка перечисляет правила.

## От чего защищает (модель угроз, SEC-27, решено 14.10)

guard ловит **ошибки агента**: запись не в своё направление (domain), правку чужого файла штаба
(pantheon-acl), правку защит не той ролью (protect-config), команду пульта не той ролью, чтение ключей
(tg-secret), пометки об авторстве Claude, свой dev-сервер; с шага 1.2 — по ролям Пантеона: личное (private: `me/`,
ключи git-crypt, журнал штаба — только hq, chiron и mnemo-brain; ключи — никому из ролей), браузер владельца
(cdp-role: демон — prometheus читает, мастерская действует; прямой отладочный порт и WebFetch на локальные адреса —
никому; ловит по номеру порта, а не по записи адреса; у WebFetch — ещё имена вроде localtest.me и nip.io, а при Surge
имена разрешаются в 198.18/15 и настоящий адрес не виден — это предел правила), push (только в свою ветку, не в main/master, без force — в том
числе `+ветка` — и удаления; `gh api` с записью — нет; `gh pr merge` — только главная сессия координатора в папках своего направления, защиты — только Метида по «да» владельца, подробно — раздел «Слияние PR»; координатор с личным в папке — mnemo-brain —
не отправляет и не сливает сам; отправляют только свой репозиторий — папки своего направления), печать в терминал (terminal: osascript, tmux
send-keys и т. п. — ввод от имени владельца), пополнение корпуса (corpus-role: `corpus add`, `channel --videos`,
`krisp`, скрипты Krisp и Диска и их ключи в Связке — ни одной роли, только через посредника; штабу корпус закрыт целиком). dev-серверы субагентам dev-* и talos в своей worktree — можно.

От **намеренного обхода и внедрённых инструкций** он не защищает: что пишет программа изнутри
(`python script.py`, `node -e`, `make`), он не видит, а свой разбор Bash мы больше не наращиваем. Настоящая
граница:

- **песочница macOS** в окнах ролей (SEC-19, SEC-26) — её собирает `pantheon domains build` в
  `~/.local/state/pantheon/settings/<направление>.json`;
- **управляемые настройки** `/Library/Application Support/ClaudeCode/managed-settings.json` (SEC-28) —
  главные запреты и хук guard, которые не перебить настройками проекта и модами.

Находку проверки безопасности по разбору Bash разбираем как «ошибка агента или граница песочницы», а не как
новый раунд поиска обходов.

## Режимы и поведение при сбое (SEC-10, SEC-29)

| Запуск | Кто вызывает | Сбой всего скрипта |
| --- | --- | --- |
| без аргумента | хук этого плагина | пропускает действие; если guard уже вызывают управляемые настройки (`--managed`), хук плагина молчит |
| `--managed` | хук из управляемых настроек | пропускает действие |
| `--strict` | хук окна роли с `onFailure: "block"` | выход 2 — действие остановлено; таймаут или пропавший файл тоже останавливают |

Внутри: сбой правил-подсказок (dev-server, attribution, cdp, nextjs) пропускает действие; сбой проверки прав
(domain, pantheon-acl, protect-config) и tg-secret останавливает роль. Каждый сбой — строка в
`~/.local/state/pantheon/logs/guard-failures.log` (время, режим, место, тип ошибки; без текста команды),
строка статуса показывает число сбоев за сутки.

## Слияние PR: три режима (metis-0038, guard 0.5.0)

**Включение.** Новая схема включается строкой `[merge_client]` в policy.toml (даже пустой таблицей) — это шаг
Метиды. До этого для своих папок всё как в 0.4.7: сливают только направления из `[merge]`, в его папках, `-R` — из
`[merge_repos]`; Гермес и Афина без `[merge]` не сливают. Режим защит (только Метида, по согласию, одно «да» — одно
слияние) и все проверки сбоев действуют сразу. Внутренние папки Метиды без `[merge]` до включения закрыты.

`gh pr merge` разрешён только главной сессии координатора направления (`domain-coordinator` без `agent_id`).
Субагентам, лидам, dev-*, argus, штабу и мастерской — отказ: они отправляют свою ветку, открывают PR и пишут в
отчёте координатору, что проверено и что меняется. Координатор с личным в папке (mnemo-brain, `[private]`) не
сливает, как и не отправляет: третье свойство (наружу) ему закрыто.

Режим guard выбирает по папке, из которой запущена команда (cwd сессии, без `cd` в самой команде), и по
репозиторию, в который сольёт gh:

| Режим | Где | Кто | Что ещё проверяет guard |
| --- | --- | --- | --- |
| Защиты | папки `[coordinators] metis-pantheon` (agent-kit, ~/.claude…) или их репозиторий | только Метида | «да» владельца на этот PR, одно «да» — одно слияние, без `--auto` |
| Продукт | `[merge_client]` направления | координатор этого направления | то же, что внутреннее |
| Внутреннее | папки своего направления из domains.json (и `[merge]` — для совместимости) | координатор этого направления | `-R` из `[merge_repos]`, с `-R` — номер PR |

**Защиты узнаются по пути и по репозиторию.** gh сливает в репозиторий из git remote папки, а не в папку. Поэтому
guard читает `git remote -v` у каждой папки защит с `.git` и сверяет с репозиторием команды: значением `-R`, а без
него — remote папки cwd и `remote.<имя>.gh-resolved` (gh repo set-default, кроме «base»). Клон, форк с
set-default, worktree или симлинк agent-kit в любой папке — тоже защиты. Сверка защит и согласия идёт по
owner/repo без хоста: псевдоним ssh (`git@gh-work:latark/agent-kit`) gh понимает как github.com. Проверка идёт
раньше реестра: если domains.json по ошибке отдаст agent-kit другому направлению, слить его сможет только Метида.
Реестр для слияния — только `~/.local/state/pantheon/domains.json`, без отката на старый
`~/.claude/hooks/domains.json`: там направления шире.

**Своя папка — по самому длинному корню.** Владелец cwd — направление с самым длинным совпавшим корнем в
domains.json, и оно должно совпасть с направлением папки запуска. Корень вроде «~/projects» у одного направления
не открывает папку другого внутри.

**Согласие на защиты** (и на любой `-R` у Метиды: `-R latark/agent-kit` из внутренней папки иначе обошёл бы его):

1. Зевс задаёт владельцу вопрос окном вопросов: «[metis-NNNN] Слить https://github.com/latark/agent-kit/pull/N?».
   Ссылка — `github.com/<owner>/<repo>/pull/<N>` или `<owner>/<repo>#<N>`, ровно один PR в вопросе.
2. Хук answer плагина pantheon пишет выбор в `~/.local/state/pantheon/owner-log/zeus.md` с пометкой
   «· окно вопросов» и телом «вопрос: [metis-NNNN] …».
3. Метида сливает `gh pr merge N --subject "[metis-NNNN] …"` (или `-t`) не позже чем через сутки. Номер в команде
   обязателен и должен совпасть с номером в вопросе, а репозиторий вопроса — с репозиторием команды.

guard ищет такую запись за последние 24 часа. Согласие — только ответ, который начинается с «Да» (без учёта
регистра, после «Да» не буква и не цифра): «Да — слить», «да», «ДА.». Вариант согласия Зевс пишет «Да — …». Не согласие:
любой другой ответ («Нет — …», «Отложить», «Отмена», «Дальше», «Да1», «No», пустой), свободный текст в окне («· окно
вопросов, свой текст»), галочка на доске (board.jsonl), id только в теле, вопрос без ссылки на PR или о нескольких
PR. Ответ — только вторая строка записи («ответ: …» сразу после «вопрос:»): строка «ответ: Да» в заметке владельца
ниже не считается. id в журнале сравнивается без учёта регистра ([METIS-0038] — тот же id), а в
`--subject` пишется строчными. Ответов на один id и PR несколько — решает последний. `--auto` при слиянии защит —
отказ: согласие действует на момент слияния.

**Одно «да» — одно слияние.** Использованное согласие отмечается отдельным файлом в
`~/.local/state/pantheon/merge-consent/` (папка 0700, файл 0600). Имя файла — sha256 от id, времени записи окна,
репозитория и номера PR, внутри — то же плюс сессия, tool_use_id и время слияния. Отметка ставится атомарно:
временный файл (O_EXCL, без перехода по симлинку), fsync, затем `os.link` в окончательное имя. Если отметка уже есть,
link падает, и второй вызов, даже параллельный, получает отказ: нужен новый вопрос окном. Хук плагина и строгий хук
окна видят один tool_use_id, поэтому один вызов не считается дважды. Перед отметкой guard заново сверяет согласие в
zeus.md: если запись окна изменилась между проверкой и отметкой — отказ. Новый ответ на тот же id получает новое
время, и слияние снова открыто, например после упавшего слияния. Отметку ставит сам хук и только когда весь вызов
разрешён: если другое правило отказало, «да» не сгорает. Роли в эту папку не пишут (pantheon-acl).

**Любой сбой — отказ.** Нет policy.toml (или Python без tomllib), нет непустого списка `[coordinators]
metis-pantheon`, `[private]` или domains.json не разобрать, git не ответил, у папки защит с `.git` не читается
remote, cwd не репозиторий или без remote, zeus.md или отметка не читается, zeus.md, папка отметок или отметка — симлинк, время записи не
разобрать, запись из будущего — слияние закрыто.

**Предел.** guard — хук PreToolUse: он проверяет состояние в момент вызова. Что изменится после того, как он ответил
«можно», и до запуска gh (подмена симлинка cwd, правка git config или zeus.md), он не видит. По модели угроз это уже
намеренный обход, а не ошибка агента, и граница здесь — песочница окна роли.

**Что guard не видит — обязанность роли.** Внутреннее — сливать после зелёных тестов и «принять» от argus. Продукт
для клиентов — то же, плюс проверка talos, строка Зевсу «что ушло» и откат одной командой в STATUS. Тексты отказов
напоминают об этом по режиму.

Везде закрыто: `--admin` (и `--admin=…`), `GH_REPO`/`GH_HOST`, `cd` в команде, PR ссылкой или `$N` вместо номера,
`-R` не из `[merge_repos]` своего направления, `gh api` с записью, push в main и master.

## Управляемые настройки (SEC-28)

Ставятся один раз на Mac, в вашем терминале (нужен пароль):

    sudo mkdir -p "/Library/Application Support/ClaudeCode"
    sudo install -m 644 ~/.claude/plugins/marketplaces/agent-kit/plugins/guard/managed-settings.json \
      "/Library/Application Support/ClaudeCode/managed-settings.json"

Файл — `managed-settings.json` рядом с этим README: запреты (ключи в Связке, `.env`, разрушительный git,
`rm -rf`, terminal-notifier) и хук guard из клона маркетплейса. Обновить — та же команда после обновления
маркетплейса. Проверка: в папке с `.claude/settings.json`, где разрешено `Bash(git clean *)`, команда
`git clean -n` всё равно получает отказ.

## Данные и выключатель

- `~/.local/state/pantheon/domains.json` — карта направлений, собирает `pantheon domains build` из
  `~/ai/pantheon/directions.toml`;
- `~/.claude/pantheon/policy.toml` — привилегии (кто metis-pantheon и mnemo-brain, доступ к личному),
  образец — `policy.example.toml`, правит только metis-pantheon;
- выключить правило: `GUARD_OFF=dev-server,nextjs` в `env` файла settings.json.
