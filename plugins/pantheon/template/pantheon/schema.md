# Устройство папки Пантеона

Папка `~/ai/pantheon` — рабочие файлы системы. Её содержимое пишут Пританей и команда `pantheon`, а не вы вручную.

- `directions.toml` — реестр направлений и ваши общие настройки (раздел `[person]`).
- `directions/<направление>/` — папка направления: его задачи (`tasks/`), передачи дел и заметки.
- `inbox/` — входящие: сюда попадает всё, что ещё не разобрано по направлениям. Заявку направлению кладут новым файлом
  в `directions/<имя>/inbox/`.
- `board.md` — общая сводка Пританея: что идёт сейчас.
- `decisions.md` — журнал решений: дата, решение, почему.
- `schema.md` — этот файл.

## Задачи

Задача — файл `directions/<направление>/tasks/<id>.md` с короткой шапкой YAML (id, название, статус, проект,
направление, кому, следующий шаг) и текстом. Создают и меняют их командой `pantheon task`: она ставит номер,
дату и журнал и проверяет шапку. Статусы: `inbox` сырое, `todo` очередь, `doing` в работе, `waiting` ждёт,
`review` на проверке, `done` готово, `dropped` отменено. Проверить все файлы — `pantheon check`.
Поле `executor` — кто пишет код задачи: `auto` (по умолчанию, решает лид), `claude` или `codex`; набор исполнителей
установки показывает `pantheon executors`.

**Завести задачу.** Текст (`--text`: цель и «Готово, когда») обязателен — без него `pantheon task new` отказывает, код 2.
Задаче пачки нужны ещё `--parent`, `--mode` и `--mode-why`:

```
pantheon task new --direction <направление> --title "Починить выгрузку отчёта" --parent "<id пачки>" \
  --mode single --mode-why "один файл, один разработчик" --text "Выгрузка падает на пустом периоде: вернуть пустой файл." \
  --done-when "тест на пустой период зелёный"
```

Задача вне пачки — без `--parent`, `--mode` и `--mode-why`. Вопрос владельцу — карточка с `--question`, `--why` и двумя и
больше `--option`; в тексте вопроса её id в виде «[<id>]».

## Уровни и названия — одни для всех направлений

Уровней четыре: **Проект → Цель → Пачка → Задача**. «Готово, когда» — чек-лист внутри задачи, а не уровень.

- **Проект** — запись в `directions.toml` (поле `project` направления). Задачи проекта видны на его заметке в пульте.
- **Цель** — результат на 1–6 недель из двух и больше пачек. Это карточка `type: story`, в которой лежат пачки
  (у пачек `parent: <id цели>`). Название — «Цель: <результат>», без слова «Пачка» и без номера. Заводит Пританей или
  координатор после «да» владельца.
- **Пачка** — набор задач под один бюджет (`estimate`, % недели) и один порядок. Тоже `type: story`, у её задач
  `parent: <id пачки>`. Название — «Пачка: <результат одной фразой>». Номера в названии нет: порядок задают поле `order`
  или срок. Заводит координатор направления. Ночной запуск — это поле `night` пачки, а не отдельная пачка.
- **Задача** — `type: task`. Название — глагол и что получится. Задача без пачки допустима, это свободная очередь.

Слово «пачка» значит только пачку из этого списка: не ночной запуск и не цель.

**«Кто делает» — поле `mode`:** `self` — координатор сам, `single` — один разработчик, `parallel` — несколько
разработчиков параллельно (нужно поле `touches`), `undecided` — не решено. В пачку задача попадает только с решённым
режимом: `undecided` там — ошибка `pantheon check`. Открытым задачам без `mode` значение `undecided` ставит разовая
команда `pantheon task migrate-mode` (сначала `--dry-run` — только план).

`pantheon check` проверяет поля задач всех направлений одинаково и печатает сводку по каждому: открытых задач, без пачки,
без «Готово, когда», без «Кто делает», «не решено», открытых остатков. Правила названий пачек и целей действуют для
карточек, созданных с 27.10.2026; старые названия не штрафуются, кроме двух открытых пачек с одним названием.

## Доска владельца

Карточки задач рисует планировщик раз в минуту в отдельной папке для просмотра. Перенос карточки — ваше решение:
планировщик записывает его в задачу и в журнал ваших слов. Значок проекта на карточке берётся из поля `mark`
направления в `directions.toml`.

Необязательное поле направления `old_folders = [...]` — прежние пути его папок (после переезда). Реестр и `pantheon
check` его не проверяют; замер `scripts/baseline.py` по нему относит старые транскрипты из этих папок к направлению.
